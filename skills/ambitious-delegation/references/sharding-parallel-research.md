# 大規模調査をパラレル委譲で分割するレシピ（delegate_task）

数百件以上の per-item 調査（例:歌手リスト全員のアルバム調査、商品リスト全部の価格調査）を1セッションで順に回すと遅くて文脈を食う。Shared-Filesシャーディングで10並列にする。サブエージェントは各自のコンテキストを持つが**同じsandbox/ファイルシステムを共有する**のがポイント。

## 手順

1. **入力リストをN個に分割（N=10/pinまで）して / 各チャンクをファイルに書く**
   `chunks = [list[i::N] for i in range(N)]` → `artists_0.txt` … `artists_9.txt`（各~96名）。

2. **アーティスト毎の除外対象（held/owned）データを「チャンク毎のJSON」として別途書く**
   `owned_{i}.json` = {item名: [除外リスト]}。パラレル委譲子は各タスクの context には全部の入力を持てない（文脈上限）ので、ファイルパスを渡し読み込ませる。全体の除外マップを dict 化して `{k:sorted(v)}` で json.dump（ensure_ascii=False）。

3. **10個の delegate_task を1回のtool_callで spawn**（各タスクの goal に自分のチャンクパス・ownedパス・出力パスを明記）。子は `web_search` 等で調査し、**結果を自分の固有ファイル `result_{i}.md` に書き出す**。異なる子が同じファイルに書かない（競合・結合事故）。

4. **抽出物/調査結果は「検索で実際に見たもの」だけを要求する**。
   「URLは検索結果に出た物を正確にコピー、推測・捏造厳禁」。サブエージェントの要約は自己申告なので、外部副作用(URLなど)は子が検索で観測した実物のみ許可し、要約だけでは鵜呑みにしない。

5. **時間管理を各子に明示**
   「1アイテムあたり検索2〜3回に抑え、見つからなければ次へ」と書く。全件網羅させるより「見つかったものだけ出力」と割り切り、遅延を防ぐ。

6. **親は終端を1行だけ出して回れを止める**
   結果は background でターン間の新メッセージとして返る。pollしない。全子完了後、各 result_{i}.md を read して結合。

## ピットフォール

- **空白/空行・『該当なし』注記を書かせるな**。子に「該当なしは行に書かない・注記禁止」と明示しないと、結合時にノイズになる。
- **各子の goal に出力フォーマットを一字一句指定**（アーティスト名\nアルバム名(年)\nURL\n空行）。フォーマット自由度が高いと結合スクリプトが破綻する。
- 子へ渡す context は最小に（ファイルパスだけ渡して読ませる）。入力が大きい時は context 文字列に貼らず共有ファイル経由にする。

## このパターンを使う道具

- delegate_task（spawn、複数task一括）
- per-chunk入力生成: 素のPython（ファイルI/O + json）で十分。
