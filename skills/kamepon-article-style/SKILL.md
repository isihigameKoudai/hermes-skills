# かめぽん流の技術記事執筆スタイル

**Trigger:** 技術ブログ記事、技術解説、実装ガイドを執筆する際に、かめぽんらしい親近感・実践性・透明性のあるトーンで書きたいとき

## あなたらしい執筆の5つの柱

### 1. **試行錯誤のプロセスを共有する**
- 最終結果よりも「どうやって辿り着いたか」を重視
- 外れた仮説・破棄したアプローチも記載する
- 計測 → 仮説 → 検証 → 書き換え のループを見せる
- 「最初は X だと思ったけど、実は Y だった」という反転をストーリーに組み込む

**例:**
```
最初の仮説：「Member 本体の ILIKE が重いんだろう」
→ EXPLAIN ANALYZE で調査
→ 実際の真犯人：タグ検索の相関サブクエリ（9,051 回のループ）
```

### 2. **ステップバイステップの実装ガイド**
- 環境構築から動作確認まで、実装フロー全体をカバー
- スクリーンショットや画像を交えて具体性を上げる
- コード例は「コピペして動く」レベルで完成度を高める
- 各セクションに小見出しを付けて、進捗を明確にする

### 3. **親近感とカジュアルなトーン**
- 自分の視点で「俺は～～した」「～～だと感じた」と書く
- 「いかがだったでしょうか」「ぜひ最後まで読んでみてください」など、読者に語りかける
- 「未来ありますよね」「かなり強いので」など、ラフな表現を活用
- ただし、ラフさと正確性のバランスを取る

### 4. **データと透明性で信頼を勝ち取る**
- 計測結果は具体的な数字で：「3.92秒 → 277ms（93% 削減）」
- 計算過程も見せる：「2,193 × 約 4 ≒ 9,051 回」
- 「〇〇という判断をした理由」を説明する
- 不確実な部分は「たぶん」「はず」と限定する

### 5. **構成と可視化で複雑さを整理する**
- 最初に全体像（アーキテクチャ図・テーブル構成）を示す
- 複雑なSQL や仕組みは図解・テーブルで視覚化
- 目次的な「概要」セクションで読者が読む前に全体をつかむ

## 記事の基本構成テンプレート

```markdown
# [タイトル]

## 概要
- 対象システム・課題の簡潔な説明
- 最終結果の数字
- この記事の主張・学び（結論を先に）

## [メインパート 1]
### 背景・問題提起
### 計測・分析（数字を出す）
### 仮説
### 試行錯誤のプロセス

## [メインパート 2]
### 修正・実装

## 結果
- ビフォー / アフターの比較（表形式が効果的）
- 改善率・具体的な数字

## ハマりポイント・学び
- 「仮説はあくまで仮説」
- 「一番太いところから順番に手をつける」
- 「DB に手を入れる前に、アプリ側でクエリ構造を整理できないか考える」

## まとめ
- この記事で何を学べたか
- 次のステップ・応用例
- 「最後まで読んでいただきありがとうございます」で締める

## 参考
- 記事内で引用した資料・ドキュメントへのリンク
```

## トーン・表現の具体例

| 場面 | あなたのスタイル |
|------|----------------|
| 問題紹介 | 「～が遅いな」「～に辿り着く」 |
| 計測結果 | 「9,051 × 0.382ms ≒ 3,466ms が積み上がっている」（計算見せ） |
| 判断理由 | 「アプリ側のSQL構造改善のほうが、影響範囲を局所化できる」（背景を説明） |
| 不確実さ | 「たぶん」「はず」「のではないか」で限定 |
| 体験談 | 「改めて感じたのは、～ということでした」 |
| 締め | 「～がおすすめです」「では！」 |

## ピットフォール

❌ **避けるべきこと**
- 完璧な結論から始める（試行錯誤を隠さない）
- スクリーンショットなしで環境構築手順を説明
- 外れた仮説・失敗を排除する（プロセスが見えなくなる）
- 一つの表現だけで数字を伝える（計算過程も見せる）
- 読者への呼びかけなしで淡々と終わる

## 活用例

### パフォーマンスチューニング記事
- 「計測→仮説→プラン読解→書き換え→再計測」ループを見せる
- EXPLAIN ANALYZE の出力を引用
- 修正前後で条件を揃えて比較

### 環境構築ガイド
- スクリーンショットでUIの手順を明示
- コード例は「コピペして動く」レベルで
- 「以下の様に表示されたら成功」と確認ポイントを明示

## 記事を書く前のチェックリスト

- [ ] 試行錯誤のプロセスが見える構成になっているか
- [ ] 計測結果は具体的な数字で示しているか
- [ ] スクリーンショット・図表で複雑さを整理しているか
- [ ] 読者に語りかける表現が入っているか
- [ ] ハマりポイント・学びセクションで「なぜこうしたのか」を説明しているか
- [ ] 最終結論が冒頭の「概要」に集約されているか
- [ ] 親近感を持たせるラフな表現が入っているか（ただし正確性とのバランスを取る）
- [ ] 参考リンクで信頼性を補強しているか
