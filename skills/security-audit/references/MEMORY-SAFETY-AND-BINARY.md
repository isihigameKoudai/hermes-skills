# メモリ安全性とバイナリ

ネイティブ／バイナリ／カーネル対象。あらゆる境界・生存期間を、攻撃者が制御する入力と全呼び出し元から再導出し、最悪の受入ケースに対して検証する。パニック/サニタイザ発見/クラッシュは、現実的な信頼できない入力がそこに達した場合のみ欠陥の証明になる。ローカルハーネス＋サニタイザ＋決定性並行テスト＋ファジング＋デバッガで検証し、不変条件の違反＋観測可能な影響を示したら止める。アセンブリ、JIT、カスタムアロケータ、オブジェクト内アクセス、外部ライブラリはサニタイザの網を逃れうるので、計装される命令を特定する。

## 境界・整数・表現

- **範囲外の読み書き** — 長さ/オフセット/インデックス/終端が固定/確保バッファの境界を越える。接頭辞・アラインメント・パディング・終端の後の残量を再計算し、送信元と送信先の容量、宣言長を信用する前の短い読み取りを確認。
- **整数のオーバーフロー・アンダーフロー・切り捨て・符号** — 確保/コピー/ループ/インデックス/ポインタ操作前の攻撃者制御の算術。高頻度パターン: `a - b`（`b > a`）、`個数 * 要素サイズ`、型最大近傍の加算、負→符号なし、64ビット長の32ビットへの縮小、番兵 `-1` が巨大サイズ化。後で使う検証済み表現を確認。
- **単位とポインタ深さの混同** — バイト/要素/コード単位/ページ/ワード/ワイヤ単位/ネストポインタ要素サイズの取り違え。解析・検証・確保・API境界・コピーで単位を比較。確保と同じ誤った単位で境界を確認してもなお誤り。
- **未初期化・部分初期化データ** — バッファ/パディング/構造体/ベクタ容量が初期化前に返され・比較され・ハッシュされ・直列化され・境界を越えて渡される。観測可能な消費者＋現実的な出力長を要求。スタック確保だけでは開示ではない。

## 生存期間・型・並行性

- **use-after-free・古いビュー・二重解放** — 所有者が解放されても、コールバック/待ち行列/タイマ/イテレータ/借用スライス/キャッシュ生ポインタが使える。全エラー/取消/クローズ/再確保経路を確認。通知アンカー: 各解放経路が全オブザーバを排出・分離する。
- **型混同と不正なダウンキャスト** — タグ/vtable/共用体判別子/オブジェクト種別/外部ハンドルが、後で読む表現と異なるチェックを受ける。未検査の動的キャスト、再利用後の古いタグ、検証済み要素と消費要素の食い違いを確認。
- **参照カウントと所有権の競合** — 非原子のretain/release、チェックと非ロック使用、クロススレッド所有権の不一致が、アクセス中に解放/変更させる。同じロック＋所有規則に対する高速/エラー/停止/互換経路を比較。
- **共有状態の競合とTOCTOU** — 並行パーサ、大域キャッシュ、遅延初期化、シグナルハンドラ、資源破棄が境界/ポリシー/ポインタを無効化する。再現可能なスケジュール/バリア/スレッドサニタイザで検証。セキュリティ上の遷移を伴わない仮想的インターリーブは要検証。
- **ロック順序・デッドロック・飢餓** — 外部到達操作が不整合な順序でロックを取る、またはコールバック/ブロッキングI/Oをまたいで保持する。有界な入力が共有進行を止める場合のみ可用性として報告。

## FFIとABI

- **ポインタ長と所有権契約の不一致** — 呼び出し側と被呼び出し側が、誰が確保/解放/固定/変更するか、ポインタ有効期間、バイトと要素の長さで食い違う。各 `extern`、CGo/JNI/Python/ネイティブ束縛、生成ラッパの両側を追う。ヌル、ゼロ長、エイリアシング、コールバック保持を確認。
- **レイアウト・アラインメント・列挙の不一致** — 構造体/ビットフィールド/パック済みレコード/コールバック署名/整数幅/列挙/呼び出し規約がアーキテクチャ/ビルドフラグで異なる。`repr`、パッキング、アラインメント、エンディアン、ABI固有型を検証。不透明な外部実装は要検証。
- **巻き戻し・例外・スレッド親和性の違反** — 巻き戻しを禁じるABIを例外/パニックが越える、破棄後にコールバックが走る、単一ランタイムスレッドを要求するAPIを別スレッドで呼ぶ。エラー変換＋取消を確認し、中止か状態破壊かを確定してから影響を付ける。

## バイナリ読み込みとランタイム

- **ライブラリ・プラグイン・実行ファイルの検索順序の信頼** — 特権プロセスが、低信頼主体が書けるパスからライブラリ/プラグイン/ランタイム/ヘルパーを読み込む、または攻撃者が影響できる作業ディレクトリ/環境から素の名前を解決する。意図したインストール所有と各フォールバック/互換検索経路を比較。自分自身のプロセスに自分のプラグインを読み込むのは境界違反ではない。
- **成果物識別・署名束縛の欠落** — ローダが一つのファイル/メタデータを検証しつつ別のイメージを写像する（パス解決、ファイル置換、アーキテクチャスライス、検証に束縛されない埋め込み資源）。ローカルの検証⇄写像ギャップ（サプライチェーンの真正性は `SUPPLY-CHAIN-AND-RELEASE.md`）。
- **不正なバイナリメタデータと再配置処理** — オフセット/件数/セクション/再配置/シンボル/バイトコード/デバッグメタデータを、範囲/重複/表現の確認前に信用する。有界なローカルフィクスチャ＋サニタイザでパーサをテストし、メモリ破壊と安全に拒否される不正ファイルを分ける。
- **JITと生成コードの一貫性** — 検証器/インタプリタ/最適化器/生成コードが型/境界/副作用/生存期間で食い違う。同じ入力で最適化と非最適化経路を差分。言語意味論内の出力差は所見ではない。
- **アンロード・再ロード・破棄の安全性** — モジュールアンロードやランタイムリセット後も、生きた関数ポインタ/コールバック/ワーカースレッド/データビューが残る。停止＋失敗ロードの後始末を起動と同程度に精査。

## カーネルと特権インターフェース

- **ユーザーコピーの境界と反復読み取り** — システムコール/ioctl/ドライバ/カーネルパーサが、ユーザーメモリから信頼する事実を導き、同じ可変アドレスを再度読む。要求全体を一度コピーするか、後のコピーを再検証。各ユーザーコピー原始要素でサイズ/方向/アクセス検査を監査。
- **特権オブジェクトの生存期間とディスパッチの一貫性** — 外部到達オブジェクトの不均衡なretain/release、オブザーバ排出なしの破棄、未検査のセレクタ/テーブル索引、防御を欠く重複互換経路。各ディスパッチ＋解放経路を並べて差分。
- **権限不足の強力なインターフェース** — デバイスノード、管理ソケット、ヘルパー、管理APIが形状は検証するが、資源に対する呼び出し元の権限を検証しない。実際のインターフェース所有と到達性を確定。リポジトリ外の権限/サンドボックスは要検証。

## 全般の手がかり

- 修正と重複経路を、同じソース→シンク形状について監査（一つの呼び出し元/アーキ/役割/フラグ/互換経路のチェックが兄弟を守らない）。
- パーサ/FFI境界ごとの表を作る: 受け入れる長さ/型、検証済み表現、確保所有者、消費者、スレッド、破棄（ネイティブ所見の大半はこの表の一つの食い違い）。
- 既存コーパス＋小さなローカル生成の境界フィクスチャを使い、正確なサニタイザ出力＋トリガー入力の性質を保存。

## 確認の要点

- 現実的な信頼できない入口＋境界/型/生存期間/ABI/並行性/ローダ/権限の不変条件を破る正確な操作。
- 観測可能な効果を分類: 不正読み取り、不正書き込み、古い別名、誤ったオブジェクト、未初期化出力、不正なイメージ読み込み、デッドロック、安全な終了。観測を超える効果を主張しない。
- 最も狭いローカルハーネス/テスト/サニタイザ/ファザーで検証し、欠陥操作のサニタイザ網羅を確認し、アーキ/ビルドを記録。
- 並行性は決定性スケジュール/サニタイザトレース。バイナリ読み込みは「検証済み識別≠写像識別」を証明し低信頼の書き手を名指す。
- confirmed は正確な入力＋ソーストレース＋観測結果がある時のみ。要検証は未解決の到達性/ABI/ビルド/配備/ランタイムの事実を具体的に。
