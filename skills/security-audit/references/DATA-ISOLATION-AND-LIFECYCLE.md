# データ隔離とライフサイクル

複数テナント・複数所有者のデータを扱うシステム。レコード上のテナント/所有者フィールドは隔離ではない。各読み書き経路で実際にそれを強制するクエリ・キー・パス・ポリシー・行レベル制御を探す。派生コピー（無害化した主データ→検索/キャッシュ/分析/エクスポート/プレビュー/ログ/レプリカ/バックアップ）を、ACLと保持期間の違いごとに追う。削除と失効はライフサイクルの契約であり、現行・履歴・キャッシュ・索引・エクスポート・復元・キュー済みの全コピーを確認する。プライバシー/保持の選好そのものは所見ではない。

## テナントとオブジェクトの隔離

- **テナント・所有者強制の欠落** — 読み取り/更新/削除/一覧/件数/バルクのクエリが、認証済みのテナント/所有者へ束縛せずにオブジェクトを特定する、またはその識別を本文フィールドに頼る。直接参照、入れ子関係、バックグラウンド、管理、インポート、旧経路を比較。
- **複合キー・名前空間の衝突** — キャッシュキー、オブジェクトパス、DB一意性、検索文書ID、一時ファイル、重複排除キーがテナント/環境を省く。別所有者が同じ論理キーを上書き・取得する。
- **ポリシーとクエリの不一致** — 行レベルポリシー、ORM既定スコープ、認可フィルタ、生/迂回クライアントが異なる述語を適用。結合、集計、別名、ビュー、トランザクション、`unscoped`/サービス接続、コンテキストを欠くエラー経路を確認。
- **ブロブと署名付き参照の過大権限** — オブジェクトキー、添付ID、バージョンID、共有リンク、署名付きURLが発行者の権限を超える操作/名前空間を許す、または基のACL変更後も有効。操作・正確なオブジェクト/バージョン・audience・期限・テナントに束縛。

## 派生データと開示

- **検索・キャッシュ・索引のACLドリフト** — 主レコードのACL/ライフサイクルが変わっても、検索可能/キャッシュ/埋め込み/サムネイル/RSS/プレビュー/索引コピーを無効化しない。取得時フィルタ＋投入＋無効化を確認。
- **分析・ログ・トレース・診断が別の読み手に** — 非公開内容/資格情報が、より広いアクセス・長い保持・テナント混在のシステムへ出る。フィールド名/公開識別子/運用者向け内容は、意図したポリシー下では不十分。
- **列挙と集計オラクル** — 件数、フィルタ、順序、エラー、一意制約、タイミング、通知、存在チェックが保護されたオブジェクト/アカウント状態を漏らす。具体的な秘匿述語＋観測可能な差を要求。

## エクスポート・バックアップ・復元・移行

- **エクスポート/バックアップの範囲拡大** — エクスポート/スナップショット/ポータビリティ/レポート/バックアップが、他テナント、アクセス外フィールド、論理削除データ、秘密値、履歴を要求者の権限を超えて含む。選択後の項目ごとの認可＋最終成果物のダウンロード認可を確認。
- **インポート/復元の権限拡大** — 復元/インポートが所有者/スキーマ/ACL/一意性/検証を迂回し、既存を上書き、または要求者が書けないテナントにレコードを再生成。アーカイブ内容を信頼できない入力として検証し、以前の来歴ではなく結果の操作を認可。
- **移行の既定値と所有権の混同** — 旧レコードがテナント/ACL/ライフサイクルを欠き、互換性のないIDが衝突、部分ロールアウトで新旧リーダーが別の既定を適用。バックフィル、二重読み書き、互換、ロールバック、再開移行を確認。
- **バックアップとレプリケーションの境界ドリフト** — 暗号鍵、ストレージアカウント、リージョン間レプリカ、復元環境、サポートスナップショットが主より広い識別/テナント範囲を持つ。リポジトリ内ポリシーは確認可能、ホスト側のアクセス/保持は要検証。

## 削除・失効・ライフサイクル

- **論理削除・トゥームストーン迂回** — 直接参照、検索、関係走査、オブジェクトリンク、バックグラウンド処理、復元がライフサイクル述語を無視し、削除/失効済みレコードを返す・扱う。論理削除済み識別子が全参照の消滅前に再登録できるか確認。
- **古い認可と派生コピーの使用** — メンバー解除、ACL更新、同意撤回、秘密失効、役割降格が、将来の操作を認可し続けるセッション/キャッシュ/サブスクリプション/ジョブ/実体化データを無効化しない。
- **保持とキュー済み作業の追い越し** — 主で削除が完了しても、キュー済み処理/再試行/エクスポート/分析/生成成果物が約束の境界を超えてデータを再作成・保持する。冪等な削除＋トゥームストーン伝播を探す。
- **復元が不正状態を再導入** — バックアップ/取り消し/復元/レプリカ復旧が、現行ポリシーがもはや許さないデータ/資格情報/メンバーシップ/権限を復元する。復元状態を再認可し、スナップショット後にライフサイクル変更を再適用。

## 全般の手がかり

- 保護されたレコードを1つ選び、主書き込み/クエリ/キャッシュ/索引/イベント/エクスポート/バックアップ/削除/復元の経路を描き、各辺に主体とテナントを記す。
- 同一のローカルサービス手法で2つのダミーテナントを比較し、ACL変更・削除・アカウント切替・復元後に繰り返す。
- 迂回クライアント、バックグラウンドジョブ、移行、大域一意性、キャッシュキーから始める（要求スコープの識別をよく落とす）。

## 確認の要点

- 攻撃者/低信頼主体、保護データ/状態、影響を受ける所有者/テナント、代替コピー/操作、不正開示/変更を名指す。
- 意図した真実源のポリシーと、それを省く/食い違う経路を引用し、別層が同じ条件を強制していないか確認。
- ローカルはダミーテナント＋非敏感フィクスチャで、最小の観測可能なレコード/操作で止める。
- 外部キャッシュ/ストレージ/レプリカ/分析/バックアップ/保持は要検証＋所有者観測のチェック。
- confirmed は完全な系統＋具体的な境界影響がある時のみ。要検証は未解決のストレージ/ACL/無効化/保持/復元の事実を具体的に。
