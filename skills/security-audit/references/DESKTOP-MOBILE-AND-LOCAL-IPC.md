# デスクトップ・モバイル・ローカルIPC

ネイティブアプリとローカルプロセス間の境界。現実的な攻撃者（別アプリ、別OSユーザー、サンドボックス化された子、信頼できない文書、遠隔オリジン）を定める。同一アカウント内の自己害は境界違反ではない。パス・プロセス名・バンドルID・自称の送信者フィールドはピア認証にならず、OSのピアクレデンシャル、コード識別、ケーパビリティハンドル、保護されたチャネル状態を使う。ネイティブブリッジ/ヘルパーは解析後に各操作＋最終リソースを認可する。OSサンドボックス/署名/エンタイトルメント/権限/キーチェーンACL/エクスポート済みコンポーネント/プロンプトは、固定版で見える場合のみ実在の防御。

## ディープリンク・コールバック・ナビゲーション

- **カスタムスキーム/ディープリンクの曖昧さ** — 別アプリ/ページが、現セッション＋一回性コールバックの束縛なしに状態変更・データ取込・認証完了・アカウント選択を行う経路を呼ぶ。URI正規化、重複クエリ、スキーム/ホスト/パス照合、エクスポート済みアクティビティ/ハンドラポリシー、古い/再送リンクを確認。
- **アプリ・アカウント引き継ぎの混同** — OAuth/SSO/マジックリンク/招待/デバイスペアリング/パスワードレス/決済のコールバックが、誤ったインストール済みアプリ/プロフィール/テナント/保留中トランザクションに戻る。開始アプリ識別・現セッション・アカウント・プロバイダ・操作・期限に状態を束縛。
- **ファイルオープン・インテントの権限混同** — 関連ファイル、共有インテント、ドラッグ＆ドロップ、クリップボード、通知アクション、オープンイベントが、内容種別・送信者の信頼・ユーザー意図・最終対象の確認なしに特権操作を起こす。

## WebViewとネイティブブリッジ

- **ナビゲーション元とブリッジの混同** — 遠隔/攻撃者が制御するフレームが、パッケージ内容専用のはずのJS/ネイティブブリッジに達する。呼び出し時＋各ナビゲーション/リダイレクト/サブフレーム生成/ポップアップ/エラー/フォールバック後にオリジンを検証。URL接頭辞チェックや初期ロード時のチェックでは不十分。
- **過大なネイティブブリッジ能力** — 汎用ブリッジ経由でWeb内容が任意のファイル/コマンド/IPC/資格情報/システム操作を選べる。メソッド許可リスト、正規化引数、ユーザー/テナント権限、ジェスチャ/確認要件、戻り値の開示を確認。
- **WebViewのファイル/ユニバーサルアクセス** — ファイルアクセス、ユニバーサルアクセス、混在コンテンツ、デバッグ、カスタムプロトコルハンドラが、遠隔内容をアプリローカルファイル・特権スキーム・内部オリジンへ結ぶ。到達可能な保護内容の無い制限設定の欠落は強化メモ。

## ローカルIPCとエクスポート済みコンポーネント

- **IPCのピア認証ギャップ** — Unixソケット、名前付きパイプ、XPC、Binder、D-Bus、ネイティブメッセージング、RPC、共有メモリ、ループバックリスナが、OSクレデンシャル・コード識別・サンドボックストークン・チャネル所有の確認なしに低信頼ピアを受け入れる。チャネルの背後に意味のあるメソッド/開示を要求。
- **自称主体とチャネル識別の乖離** — 認証済みプロセス/チャネルは1つのアプリ/ユーザーに属するが、要求フィールドが別ユーザー/テナント/プロフィール/能力を選ぶ。各メソッド＋リソースをピアクレデンシャルに束縛。
- **エクスポート済みサービス/アクティビティ/レシーバ/プロバイダの過大権限** — 外部から呼び出せるモバイルコンポーネント/ローカル自動化端点がアプリ内部操作を行う。最終マージマニフェスト、インテントフィルタ、権限/署名レベル、パス付与、別名を確認。パッケージ後のマニフェスト不明は要検証。
- **IPCライフサイクルと相関の混同** — 予測可能な要求ID、再利用ハンドル、古いチャネル、継承記述子、誰でも書けるソケットパス、再起動挙動が、一方のピアに他方の操作を応答/取消/再利用させる。ソケット/ロック/ポート/共有マッピングの作成権限と後始末を確認。

## 特権ヘルパーとローカルファイル

- **特権ヘルパーの混同代理** — 低権限呼び出し元が特権コマンド/ファイル/サービス/ユーザー/システム設定を、操作ごとの認可なしに選ぶ。sudo/polkit/UAC/XPCヘルパーの規則を確認し、ヘルパーが正規化引数を独立に検証することを確認。
- **インストール・更新・修復経路の信頼** — 特権インストーラ/ヘルパーが、認可後に低信頼主体が書けるマニフェスト/スクリプト/パッケージ/シンボリックリンク/作業ディレクトリ/修復状態を読む。認可を不変の内容＋安全な宛先に束縛。
- **ローカルファイルの所有権とTOCTOU** — アプリがファイル/パスを確認した後、特権読み書き中に置換/シンボリックリンク/マウント/大文字小文字/正規化の変化を追う。記述子相対操作＋最終所有権の確認を使う。
- **資格情報ストアとローカル秘密の境界不整合** — キーチェーン/キーストア項目、トークンファイル、バックアップ、ログ、クリップボード、通知プレビュー、ローカル設定が、権限の低い別アプリ/プロフィール/ユーザーから読める。同一OSアカウントのみが読める平文は自動的には脆弱性でない。低信頼の読み手＋資格情報の力を明示。

## アプリ状態とデバイスライフサイクル

- **アカウント切替・ログアウト・デバイス復元の漏出** — キャッシュ、バックグラウンドタスク、ウィジェット、通知、ローカルDB、WebViewストレージ、生体承認がログアウト/アカウント変更を生き延び、後のアカウントで現れる。バックアップ/復元＋複数プロフィールを確認。
- **保留操作とユーザー存在の混同** — 通知/ウィジェット/ショートカット/共有シート/生体/遅延操作が、表示と異なる操作を認可、期限後に実行、または別プロフィールの保留状態を使う。確認を正規化した操作・リソース・アカウント・現フォアグラウンド状態に束縛。

## 全般の手がかり

- 全プロセス、アプリコンポーネント、ローカル端点、URIスキーム、ファイル関連、WebViewオリジン、ヘルパーを列挙し、OS識別・実行時権限・呼び出し元・呼び出せる操作を記録。
- 最終パッケージ入力（マージマニフェスト、エンタイトルメント、インストーラ規則、ネイティブメッセージング登録、プロトコルハンドラ、ACL作成）を読む（ソース宣言は下流で上書きされうる）。
- ダミープロフィール＋非敏感なローカルフィクスチャを隔離マシン/エミュレータで検証。

## 確認の要点

- 攻撃者の開始能力、越えるOS/アプリ主体、入口チャネル、受け入れられる引数/状態、不正操作/開示を名指す。
- OSサンドボックス/ピアクレデンシャル/署名/エンタイトルメント/権限/ユーザー同意/インストーラ制御を確認。パッケージ不明は要検証。
- WebViewはナビゲーション/オリジン制御＋特権ネイティブシンクを、IPCはピア認証＋リソース別認可を、ヘルパーは最終正規化宛先を確認。
- ローカルテストは有界、ダミー内容/アカウントで、境界結果の後に止める。
- confirmed は完全なソース＋ローカル証拠連鎖がある時のみ。要検証はOS/マニフェスト/署名/ACL/デバイスライフサイクルの事実を具体的に。
